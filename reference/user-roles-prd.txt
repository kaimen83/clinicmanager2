# 클리닉 관리 시스템 사용자 권한 시스템 구현 PRD

## 프로젝트 개요
현재 Clerk 인증 시스템을 사용하는 클리닉 관리 시스템에 4단계 사용자 권한 시스템을 구축하여, 사용자별로 적절한 접근 권한을 부여하고 보안성을 강화한다.

## 현재 상황 분석
- **인증 시스템**: Clerk 완전 도입 (모든 API 라우트에서 currentUser/auth 사용)
- **권한 시스템**: 없음 (링크만 있으면 누구나 접근 가능)
- **기존 데이터**: MongoDB에 username/password 기반 users 컬렉션이 있으나 사용되지 않음
- **보안 위험**: 모든 인증된 사용자가 동일한 권한으로 시스템 접근

## 목표
1. **4단계 권한 체계 구축**: 최고관리자, 관리자, 일반직원, 조회전용
2. **권한 기반 접근 제어**: API 및 UI 레벨에서 권한 검증
3. **권한 관리 시스템**: 최고관리자가 사용자 권한을 관리할 수 있는 기능
4. **안전한 초기 설정**: 첫 사용자 자동 최고관리자 설정

## 권한 체계 정의
각 권한별 기능은 추후에 정의할 예정입니다.

### 1. 최고관리자 (SUPER_ADMIN)

### 2. 관리자 (ADMIN)

### 3. 일반직원 (STAFF)

### 4. 조회전용 (READ_ONLY)

## 기술 요구사항

### 1. 데이터 모델
- **userProfiles 컬렉션**: Clerk ID를 키로 하는 사용자 프로필
  ```javascript
  {
    clerkId: String,     // Clerk 사용자 ID
    role: String,        // SUPER_ADMIN | ADMIN | STAFF | READ_ONLY
    name: String,        // 사용자 이름
    email: String,       // 이메일
    createdAt: Date,     // 생성일
    updatedAt: Date,     // 수정일
    isActive: Boolean    // 활성화 상태
  }
  ```

### 2. 권한 검증 미들웨어
- API 라우트별 권한 검증 함수
- 역할 기반 접근 제어 (RBAC) 구현
- 권한 부족 시 적절한 에러 응답

### 3. 권한 관리 UI
- 사용자 목록 조회 페이지
- 권한 변경 모달
- 사용자 활성화/비활성화 기능

## 구현 범위 (Phase 1)

### 필수 구현 사항
1. **userProfiles 컬렉션 생성**
   - MongoDB 스키마 정의
   - 데이터 모델 파일 작성

2. **권한 검증 유틸리티**
   - 사용자 권한 조회 함수
   - 권한 체크 미들웨어
   - 역할별 접근 권한 정의

3. **초기 설정 로직**
   - 첫 사용자 자동 최고관리자 설정
   - 기존 사용자 마이그레이션 로직

4. **권한 관리 페이지**
   - 사용자 목록 표시
   - 권한 변경 UI
   - 최고관리자만 접근 가능

5. **API 보안 강화**
   - 주요 API 라우트에 권한 검증 추가
   - 권한 부족 시 에러 처리

### 제외 사항 (향후 구현)
- 기존 기능별 세부 권한 적용
- 페이지별 접근 제어
- 기능별 버튼 숨김/표시 로직

## 성공 기준
1. **기능적 요구사항**
   - 4가지 권한 역할 정상 동작
   - 권한 관리 UI 정상 동작
   - 첫 사용자 자동 최고관리자 설정 동작

2. **보안 요구사항**
   - 권한 없는 사용자의 API 접근 차단
   - 권한 변경은 최고관리자만 가능

3. **사용성 요구사항**
   - 기존 사용자 경험 유지
   - 권한 관리 UI 직관적 사용 가능

## 기술 스택
- **Frontend**: Next.js, React, TypeScript
- **Backend**: Next.js API Routes
- **Database**: MongoDB
- **Authentication**: Clerk
- **Styling**: Tailwind CSS (기존 사용)

## 위험 요소 및 대응
1. **기존 사용자 데이터 손실**: 마이그레이션 로직 신중 구현
2. **권한 체크 누락**: 체크리스트 기반 검증
3. **성능 영향**: 권한 조회 캐싱 고려

이 PRD는 권한 시스템의 기반 구조 구축에 집중하며, 향후 각 기능별 세부 권한 적용은 별도 구현 예정입니다.
